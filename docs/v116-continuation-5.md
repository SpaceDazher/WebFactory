# Продолжение 5 — горячий цикл переноса тепла

## Статус

Три узких цикла реализации завершены. Полный `npm test`, независимое сравнение физики с предыдущими исходниками, сборка, typecheck, balance и полная RU/EN-проверка прошли. Строгий тепловой стенд всё ещё **exit 1**: p95 тепловой перестройки при split/merge выше 2 мс. Версия остаётся **1.16.0-rc.7**, общая приёмка не завершена. Четвёртый цикл реализации в этой фазе не выполнялся.

## Изменения без новой физики

1. Потери труб: прежняя последовательность Number-сложений выполняется в локальном регистре, результат записывается в `g.nuc.st.lost` один раз в конце фазы. Порядок ID, `|| 0`, дробные/ограниченные потери и округление на границе точности сохранены. Это не сложение суммы потерь с прежним счётчиком: такая замена меняет результат для больших чисел. При отсутствии потерь свойство не создаётся.
2. На затронутой ID-странице вместо двух Int32Array используется один interleaved `edgeSlots`. Каждый endpoint и порядок канонических пар сохранены; старые векторы остаются неизменяемыми. Полные диагностические edgeA/B интерфейса HeatNet не удалены.
3. Инициализация температур плотного кэша читает стабильные entity-слоты напрямую. Это независимые чтения, не аккумуляция. Для разреженного high-water кэша сохранён fallback через ID-страницы. Потоки и потери по-прежнему применяются в каноническом ID-порядке.
4. Численный перенос выделен в `transferHeat(H)` из большого `stepHeat`. Уравнения, четыре прохода ограничения потоков, целочисленное округление и порядок применения прежние. Это не второй режим физики. Перестройка, упаковка индексов и сам перенос остаются внутри реального измеряемого `Game.step`.

Механика реакторов, вода/пар, потребители мощности, аварии, заражение и сетевые команды не менялись. Не добавлены телепортация, freePower или скрытый прогрев вместо измеряемой работы.

## Диагностика и её границы

Секции прежнего continuation-4 кода измерены отдельной временной инструментализацией. Отдельно сохранён диагностический trace GC/deopt V8. В нём обнаружены повторные деоптимизации большого stepHeat; bytecode связывает один повторный offset с чтением flowJ. Это наблюдение, а не доказанная причина каждого длинного шага. Инструментализация и trace добавляют накладные расходы и не включены в приёмочные значения.

Диагностический helper сохранён с явным использованием двух замороженных continuation-4 файлов и восстановлением обоих рабочих файлов в finally. Приёмочные стенды запускались без диагностических вставок и тяжёлого параллельного процесса. Исходные отрицательные результаты всех кандидатов сохранены, включая ухудшение хвоста у первых двух.

## RED и регрессионные проверки

Новый `tests/heat-loss-register.test.ts` сначала упал на прежнем коде: счётчик записывался для каждой трубы вместо единственного commit. Проверяются нулевой/дробный/большой счётчик, MAX_SAFE_INTEGER, NaN-нормализация, clipped loss, остатки hL и отсутствие свойства на холодном шаге. Ожидание намеренно повторяет каждый старый Number-add, а не новую формулу суммирования.

Новый `tests/heat-packed-slots.test.ts` сначала упал на прежнем представлении без interleaved vector. Запрет чтения node.slot подтверждает прямую плотную инициализацию, а физическая remove/step проверяет неизменяемость старого вектора, endpoint-порядок и save/replay.

Оба теста добавлены в `npm test` без удаления или перестановки прежних команд. Старые тесты побайтно не изменены. Прежние delta-storage, local-rebuild, component-index и explosion-batch прошли; аварийный hash остаётся `999283ce28e16b6e`.

## Независимое сравнение исходников

`integration-logs/continuation-5/baseline-src` — отдельное дерево исходников continuation-4. `docs/.heat-continuation-5-parity.once.ts` загружает старую и новую реализации из одинакового сохранения, а не переключает режим нового алгоритма. На каждом шаге сравниваются stateHash, полное сериализованное состояние и весь g.nuc.

Все **600 шагов** совпали; окончательный hash `99b0d54af2df5814`. Сценарии: HX-connected split/merge, редкие ID до 2 млрд, поворот, реальная остановка командой on:true с проверкой rstop/rt, save/load, mod-capacity full fallback, удаление/восстановление HX и настоящий взрыв.

## Строгая производительность

Исходный обязательный `docs/.v116-heat-full.once.ts` не изменён; SHA256 проверен. Сохранены 100 реакторов, 12 300 горячих теплопроводов, 1000 HX, 2000 турбин, 200 настоящих насосов, 100 активных радаров. В preflight каждый HX и каждая турбина реально работали. Разрыв/соединение выполняются реальными API, граф перестраивается внутри timed step. У каждого обычного этапа прежние 300 warm-up + 1800 measured steps; split/merge — по 30 настоящих циклов. Nearest-rank p95 = ceil(0.95*N)-1, без интерполяции.

После полного набора выполнены последовательно свежий baseline continuation-4 и окончательный continuation-5. Копия стенда для старого дерева меняет только пути импортов; обратная замена побайтно восстанавливает исходный файл. Тихие контрольные повторы не являются новым циклом реализации.
