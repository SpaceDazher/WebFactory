# Продолжение 6 — отклонённый численный кандидат и проверка обычного бота

## Итог: не финальный релиз

**Новый тепловой кандидат отклонён.** Он функционально прошёл полный npm test и независимое сравнение чисел/сохранений, но исходный 2-мс heat gate не прошёл. В обоих окончательных повторах ухудшился merge-хвост относительно свежей прежней реализации. Лучший ранний замер не выбран вместо повторов.

В корневые `src/sim/heat.ts`, `src/sim/heat-cache.ts` и `package.json` возвращены **точные continuation-5 файлы**. Контрольные SHA256 совпадают с прежней замороженной успешной функциональной проверкой. Экспериментальные тесты удалены из основной цепочки вместе с отклонённой реализацией, но не уничтожены: весь вариант, patch и логи сохранены в integration-logs/continuation-6. Ни один исходный тест не удалён/изменён и ни один порог не ослаблен.

Сборка остаётся **1.16.0-rc.7**. Игровой код в этой передаче не новее continuation-5; новое здесь — результаты расследования, воспроизводимый отклонённый вариант, длительный непройденный bot-прогон и обновлённая передача.

## Проверенные попытки — три цикла реализации

1. Прямой текущий slotEntities scratch вместо многократных paged entity lookups. Изменения/удаления обновляли только затронутые слоты, dead references очищались; неизменяемые топологические снимки не мутировались.
2. Канонические pipe reference rows на затронутых страницах вместо чтения node metadata каждой трубы во время потерь.
3. Численный буфер energy transfer сохранял каждое прежнее Number-add/subtract в каноническом порядке, но выполнял один финальный entity commit. Это не суммирование net-flow перед добавлением к энергии. Отдельный hpipe port fast path устранял временные port-объекты при тех же reciprocal-port проверках.

RED каждого нового механистического теста записан до изменения. Первый flow-commit RED сначала выявил различие constructor-vs-load стартовых снимков; обе стороны теста затем приведены к одинаковому deserialize начальному состоянию, и корректный RED упал именно на множественных hE-записях. Это изменение только нового проверочного сценария, не игрового кода.

Все три новых теста, прежние packed/loss/delta/local/component/explosion, typecheck и независимые сравнения прошли. Четвёртый цикл реализации в этой фазе не выполнялся. После отрицательных повторных замеров вариант не оставлен в текущей игре.

## Независимая функциональная проверка отклонённого варианта

Предыдущий source и новый source совпали на всех **600 шагах** по stateHash, полному serialized state и g.nuc; окончательный hash `99b0d54af2df5814`. Реальные stop on:true, HX split/merge, большие ID, поворот, save/load, mod-capacity fallback, HX removal/restore и взрыв сохранены. Старый аварийный hash `999283ce28e16b6e` не менялся.

Дополнительная независимая numerical parity: **80 шагов**, входы 0, дробная энергия, signed zero, NaN и большие Number; Object.is для hE/hL, hash, saved-state и nuclear counters совпали. Входы за safe-integer границей — только математический регресс, не расширение разрешённых модов.

Эти доказательства относятся к **отклонённому** candidate-src, не к новому статусу производительности. Его замороженные файлы сохранены побайтно в rejected-candidate; диагностические parity-скрипты теперь явно импортируют этот источник и baseline-src, поэтому воспроизводят сравнение после отката основной игры.

## Тихий строгий стенд и решение

Исходный docs/.v116-heat-full.once.ts побайтно сохранён, SHA256 e094a06792499fb36e069f83b5957bff46a5449664ae8b9559c2fdb30b1d9d77. Копии старого/отклонённого стенда меняют только пути импортов; обратная подстановка даёт исходные байты.

Сохранены 100 реакторов, 12 300 горячих труб, 1000 работающих HX, 2000 работающих турбин, 200 настоящих насосов, 100 активных радаров. По 300 warm-up + 1800 обычных измеряемых шагов, по 30 настоящих split/merge. Все cache/packing/transfer операции остаются внутри timed Game.step. Nearest-rank p95 = ceil(0.95*N)-1. Profiling-инструментализация исключена; приёмочные наблюдения не исключались и не объединялись между фазами/прогонами.

Полный npm test закончился до свежего последовательного baseline/final/final-repeat. Полный бот стартовал **после** этих контрольных замеров, не создавая параллельной тяжёлой нагрузки для них.

## Обычный полный бот — прерван, не засчитан

Запущена настоящая `npm run bot`: прежние default seed/scenario/enemies, без shortcuts, выдачи ресурсов, ручной установки rockets или сокращённого `--until`. Единственное перенаправление BOT_SAVES отделило новые checkpoint-файлы от исходных сохранений. Исходные shots/bot-final и bot-report сохранены перед запуском и возвращены после прерывания.

Последний полный checkpoint: `ck-01620000.z7save`, tick **1620000**, rockets **0**, исследование `modules-3`; инженер жив.

При смене worker/session процесс и exec handle исчезли. Финальный отчёт/exit не появились. Это не успешный и не завершённый неуспешный прогон; он **не засчитывается**. Не установлен точный сигнал завершения. `ordinary-bot.interrupted` фиксирует отсутствие процесса, а не выдуманный command exit.

Checkpoint содержит мир, но не стек генератора и память планировщика. Загрузка его в игру не является продолжением того же npm run bot. Новый полный прогон требуется в окружении, которое удерживает процесс до штатного завершения. Здесь повторная тихая перезапуск-петля не выполнялась.

## Передача и оставшиеся условия

- Действующий код — continuation-5, RC.7. Исходный heat gate ≤2 мс остаётся открытым.
- Следующий отдельный тепловой этап может проверить объединение transfer/pipe-loss финальных hE commits, но только с доказательством точного Number-порядка, HX-отбора и аварийного энергетического баланса. Это гипотеза, не реализованный фикс.
- Полный ordinary bot: запускать штатный npm run bot в достаточно долгоживущем окружении; не подменять его загрузкой checkpoint.
- REF против именно 1.15, полная mega без смены golden, общая Chromium/Firefox/WebKit матрица, реальная GPU/фокусная и ручная приёмка в этом продолжении не закрыты и не повторялись. Старые отрицательные результаты не аннулированы.
