# Незавершённые границы интеграции, найденные при возобновлении

Это статический разбор исходников до завершения реализации, не результат
проверок и не перечень уже исправленных ошибок. Исполнитель получил эти
замечания. Тесты, типы, сборка и браузер в этой фазе не запускались.

| Критерий | Наблюдение в исходной незавершённой версии | Требуемый путь реализации |
| --- | --- | --- |
| Персонаж при переносе мира | `net/prepare.ts::prepareWorld` закрепляет хоста за индексом 0 и допускает поиск отключённого персонажа по имени. | Стабильная подтверждённая личность владельца/гостя; имя не даёт доступ к чужим вещам или управлению. |
| 16 участников | `Game.MAX_PEERS`, `Session` и `compat.ts` рассчитаны на восемь; импорт использует `peers.slice(0, 8)`. | Согласованные пределы создания, допуска, сохранения, миграции и повторного входа; участники 9–16 не теряются. |
| Серверный контекст | `v117Systems.ts` выбирает лимиты армии по `Game.dedicatedServer`. | Один доверенный контекст у серверной симуляции и всех клиентских Worker после входа/загрузки/переподключения; гость не переключает его командой. |

| Скрипты | В браузерном Worker используется `ScriptHost` с `browserSpawn`. | Совместимый безопасный адаптер серверного runtime; нельзя молча выключать сценарий или мод при передаче мира. |
| Огненные биопокрытия | `items.ts::V117_ALLOWED_AMMO` исключает `flame`, хотя огненный урон и `fire=true` имеют именно огнемётные смеси. | Голод биоформ | `stepForms` использует `120 * 60 * TICKS` до убывания HP, то есть 120 минут вместо 120 секунд. | Отсчитывать точные тики без пищи, согласовать момент начала голода и расход/остатки капсул без потери единиц. |

При дальнейшем разборе найден существующий серверный адаптер модов
`src/mods/script-node.ts::nodeSpawn/stepScripts`; создавать вторую реализацию
для этой задачи не требуется. Поле `stopLeft` снимка и загрузка/нормализация
пяти топливных ячеек, пропущенные при первом переносе, добавлены исполнителем
и затем непосредственно просмотрены родителем. Их работоспособность ещё
не проверена запуском.

Публичный TLS endpoint/оператор relay отсутствует. Реализация локального
сервиса и поставки сама по себе не доказывает вход из интернета, работу
установленного приложения на чистой Windows, 24 часа с 16 игроками или
проверку удобства новыми людьми. Эти свидетельства остаются отдельными.

## Дополнительные наблюдения при продолжении (не результаты тестов)

Переданы тому же исполнителю для оставшегося этапа, до общей приёмки:

- `executeMelee` использует `def.extra` только для второй/третьей цели.
  У дубинки лимит 1, поэтому её электрические 52 единицы теряются.
  Компонент одного удара следует отличать от урона дополнительной цели.
- Отдельный удар по `nest` выбирается одной клеткой на конце луча и
  добавляется после лимита обычных целей. Он должен войти в общий набор
  кандидатов по центру/сектору/дальности/LOS и применить правильные типы урона.
- `commandGenetics transfer` меняет владельца без проверки его 24W
  вместе с уже зарезервированными заданиями.
- Возврат пустой питательной капсулы использует один boolean и старое
  имя `player-1`. При полном инвентаре возможна потеря нескольких ожидающих
  пустых капсул; получатель должен разрешаться через стабильный playerId.
- Отсутствующий peer считается подключённым в `stepForms`; проверить
  удержание после 30 секунд отсутствия владельца, отдельно от голода.
- Новый `Inventory.addStack` при обычной стопке может сначала добавить
  часть, затем вернуть false. Для отката переноса требуется атомарность
  либо точный остаток, иначе восстановление исходной стопки создаст дубль.
- При извлечении повреждённого дрона из закрытого слота неудачная передача
  не должна возвращать его обычным `addStack` только в открытые слоты:
  если они полны, экземпляр теряется. Нужен предварительный контроль
  либо точный откат в исходный слот.
- Функцию `droneFactory` нельзя хранить перечисляемым own-полем Inventory:
  `snapshot` передаёт `g.inv` через Worker structured clone. Функции в
  снимке приводят к ошибке передачи. Фабрика должна оставаться вне данных.
- `quickHash` пока не охватывает metadata физического дрона в Inventory;
  JSON состояния `g.v117` не заменяет хеширование пристыкованных машин.
  Загрузка заменяет Inventory: после неё требуется восстановить фабрики.
- `validateV117Command` определён без найденных вызовов; `Game.apply`
  передаёт команду напрямую. Входы должны проверяться авторитетом с учётом
  присвоенного сетью `pl`. Некорректный opId не должен попадать в operations.
- `commandTraining` принимает произвольный id и обращается к обычному
  объекту через `||=`. Значения `__proto__`/`constructor` не должны
  разрешаться как записи обучения или менять унаследованные объекты.
- Для новых биопокрытий в боевом коде найдено только чтение accuracy.
  Metadata кислоты/замедления/радиуса/продления огня ещё требует реальных
  путей через выстрел, снаряд, попадание, огонь и всех потребителей патронов.
- После подключения физического переноса обнаружен производственный
  разрыв: `outputRoom` разрешал выпуск дрона только у боевого порта,
  хотя §6 требует производство в сборщиках. Сборщик должен один раз
  материализовать экземпляр в ограниченном выходном буфере; порт остаётся
  оборонным ангаром. Числовой output не должен порождать UID повторно.
- Прямая выгрузка логистического груза через `c.inv.addStack` обходила
  зоны боевого порта 12/4/2: дрон мог занять слот патронов/ремонта.
  Все пути назначения должны использовать одинаковые проверки ячеек,
  фильтров и доступа. Передано исполнителю до общей проверки.

§8 и §11 дополнены родителем во время реализации. Общее назначение
жидкостей, физические координаты двух прототипов и порядок шести рецептов
просмотрены в исходниках; реальные потоки, графика и сеть не запускались.
Наличие этих изменений не снимает перечисленную в ledger приёмку.
