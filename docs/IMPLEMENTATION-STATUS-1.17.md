# 1.17 implementation status

This ledger tracks every functional section of [`SPEC-1.17.md`](SPEC-1.17.md) against the working tree. It is a work log, not acceptance evidence. The initial source phase deferred all executable checks as requested. On 19 Oct, after wiring the final known acid/detonation and mechanical repair/budget gaps, unified verification began. Current results are recorded in `logs/verify-20261019/` and `RESUMED-20261019.md`; historical source-only notes below do not describe the current verification state.

Status labels: **present** means the alpha 1–5 path is already connected; **partial** means there is a usable base but SPEC behavior remains; **missing** means no working path is present in this tree; **external** means implementation can be prepared but live operation depends on infrastructure outside the repository; **pending acceptance** means the stated behavior still needs runtime evidence after implementation.

The SPEC's proposed world format 19 is stale: the protected alpha 5 base saved format 20; the implementation now uses world format 21 with a 20→21 migration, preserving the 17→18→19→20 history. Runtime/app control state has its own schema and is not world save state. The existing 341 item definitions and their indices remain fixed; additions go after the alpha 5 additions. All new format-21 behavior is still pending the deferred executable acceptance.
