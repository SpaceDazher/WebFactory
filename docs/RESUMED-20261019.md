### Дополнительные исходниковые несоответствия генетики

Лаборатория теперь занимается либо обычным рецептом выделения/анализа,
либо отдельной операцией основания/деления. Новую операцию нельзя начать
поверх уже идущего рецепта; обычный assembler не продвигается параллельно
с activity. Два лабораторных запроса не резервируют одну и ту же новую
линию в одном банке. Закончившееся, но заблокированное выходом activity
остаётся ожидающим и снимает активный расход 480 кВт (обслуживание живых
линий остаётся). Обычные рецепты дают реальные выходы в буферы, анализ
потребляет именно произведённые данные генома.

Деление больше не пишет фиктивные itemId `culture-portion-*` в input/output
лаборатории: зарезервированная материнская порция уже отражена вычитанием
из банка и activity со species. В предметных балансах остаются только
реальные жидкости; это устраняет несоответствие генератора состояния его
закрытой схеме сохранения. Проверка загрузкой ещё не выполнялась.

Биоформы используют общий расчёт немутировавшей брони/сопротивлений
исходного UnitDef; живой удар идёт через обычный hitUnit без скрытой
компенсации плоской брони и без военных бонусов оружия инженера. Старые
свойства UnitDef не изменялись. Мгновенный удалённый ремонт плоти обычным
ремкомплектом убран; legacy repair-command объясняет восстановление тканей
в питаемом посте после 30 с без боя, по 1% HP/10 с за 5W среды. Ручная
питательная капсула передаётся только с дистанции до четырёх клеток.
Все изменения ожидают общей проверки после оставшейся функциональности.

Летун теперь проходит над водой/наземными постройками и не сталкивается
с наземной биоформой/инженером; столкновения своего воздушного слоя
сохраняются. Остальные особи используют полный наземный габарит. Строй
следования рассчитывается по сортированному составу реально следующих
особей и максимальному размеру тела, а не id%24: пропуски id после потерь
больше не назначают двум особям одинаковое место. Отключение владельца и
cooldown отсчитываются также во время складывания/развёртывания червя.
Предпросмотр/исполнение используют те же правила занимаемой площади.
Исполнение всего перечисленного ещё не проверялось.

Тот же Luna/max выдал исходники настроек password/whitelist/roles/

Гостевой seed теперь используется только для Ed25519-подписи: auth несёт
`admissionPublicKey` и 64-байтную подпись одноразового world/generation
challenge. Fingerprint — SHA256 открытого ключа. Seed остаётся в
origin/world-scoped хранилище, не включается в запрос. Node22 проверяет
открытую подпись через crypto.createPublicKey JWK/verify. Временный запрет
LAN HTTP/WS убран; это не обещание шифрования LAN. Интернет-relay по-прежнему
требует HTTPS/WSS, а административный контроллер — loopback.

SHA/HMAC/PBKDF2 теперь библиотечные примитивы. Браузерный подписывающий

выполнялась внутри ESM server bundle. Лицензии включаются в HTML и native
пакет исходниками build scripts (сборки не выполнялись).
