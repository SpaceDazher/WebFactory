# Continuation-10: реакторы и электросети, 12 октября 2026

Версия остаётся **1.16.0-rc.7**. Этот этап продолжает переданный continuation-9 и сокращает пик массовой аварии. Вся 1.16 ещё не принята как финальная.

Входной архив SHA256: `cccd5b3339ff070f6e852b61ee7f16b05ef142417309d9263a003ca5da57560b` — родитель проверил совпадение с файлом контрольной суммы. Вход распакован отдельно, прежняя рабочая копия сохранена. Пользователь прямо подтвердил **p95 тепла ≤6 мс**; полный шаг по-прежнему **≤16,67 мс**. Исторические отчёты с 2 мс сохранены.

## Что изменено

- `src/sim/heat.ts`: причина перегрева вычисляет признаки по одному чтению каждого текущего статуса теплообменника. Нет кэша между изменяемыми состояниями или тиками; приоритет причин и строки прежние.
- `src/sim/networks.ts` и `src/sim/world.ts`: только на время синхронного обхода покрытия столбов переиспользуется текущий чанк. Сохранены обход клеток, создание чанков/обработчики, живой occupancy, порядок проводов/сетей и первый покрывающий столб. Методам не подменяются ссылки; учитываются переопределения, замена чанка, вложенные вызовы и исключения. Обычные occ/setOcc не ищут кэш в WeakMap.
- `tests/heat-component-index.test.ts`: проверены чтения статусов, точные причины и порядок предупреждений, включая удаление теплообменника в том же тике.
- `tests/power-rebuild-coverage.test.ts`: границы покрытия, отрицательные координаты, размеры/провода модовых объектов, равное расстояние, переопределения, обработчики нового чанка, живые записи/замена чанков и срок действия кэша. Тест добавлен в npm test; все прежние команды сохранены — родитель проверил точное восстановление прежней строки после удаления единственного добавления.
- `tests/stats.test.ts`: общий Linux-путь `/tmp/zavod7-stats-test` заменён уникальным `mkdtemp` в системном tmp. Обе CLI-проверки и их ожидания сохранены; отчёты лежат в собственной папке. Рекурсивного удаления нет. Это исправление переносимости теста, не изменение игры.

Родитель проверил область изменений по входному SHA-манифесту: из 113 производственных файлов отличаются только heat.ts, networks.ts и world.ts. Физика энергии, урона и жидкостей не менялась. Работу не переносили за измеряемый Game.step.

## Чистые последовательные A/B

Один ПК: Intel Core i7-12650H, Node v22.23.2. Порядок: baseline1 → candidate1 → baseline2 → candidate2. Без параллельных тяжёлых задач, дополнительных таймеров функций и счётчика chunkAt. Исходник стенда отличается только imports/путями выходных файлов; родитель просмотрел различия. Масштаб: 100 реакторов, 12 300 теплопроводов, 1000 теплообменников, 2000 турбин и 200 настоящих насосов. Первый взрыв везде на шаге 600, 25 инициирующих взрывов/100 зон.

| Пара | Пик полного шага, до → после | Пик тепла, до → после | Изменение полного пика | Exit до/после |
|---|---:|---:|---:|---:|
| 1 | 332,670 → 205,548 мс | 321,180 → 200,017 мс | −38,2% | 0 / 0 |
| 2 | 284,194 → 208,962 мс | 271,174 → 203,260 мс | −26,5% | 1 / 0 |

Baseline2 превысил ограничения на разрыве: 17,037 мс полного шага и 9,0505 мс тепла. Его не исключали из сравнения. **Оба окончательных кандидата прошли весь стенд.** Родитель заново рассчитал nearest-rank p95 из всех сырых массивов: 1800 отсчётов для работы/охлаждения/холодных, 30 для разрыва/соединения, 600 для аварии. Максимумы кандидата: полный шаг 11,3115 / 12,4275 мс; тепло 4,9290 / 5,7721 мс.

Два сравнения подтверждают выигрыш в этих условиях, не статистическую гарантию на всех машинах. **Пик 205–209 мс всё ещё намного больше 16,67 мс.** Зелёный p95 его не устраняет.

Исходные данные: `integration-logs/continuation-10/reactor-power/{baseline,candidate}-cycle2-pair-{1,2}/`. Таблица всех стадий: `cycle2-ab-nearest-rank-summary.json`; независимый пересчёт: `parent/cycle2-raw-recomputed.json` в той же папке.

Длинный тест: три сценария по **2 160 000 настоящих шагов (10 игровых часов)**, в каждом 0 аварий и 0 ошибок топливного баланса. Ошибки энергетического баланса: 846,873 / 90,947 / 69,752 Дж. Экономичный режим подал 316 ячеек, контроль — 816; принята физическая нормализация остатка энергии. Вычисления заняли около 766,7 секунды и частично шли параллельно функциональному npm test; это не тихий замер скорости и не десять настенных часов.

Сравнения состояния: 600 шагов с аварией/перезапуском, конечный хеш `99b0d54af2df5814`; текущие причины, статусы, nucEv, сообщения и оповещения сопоставлены после каждого шага. Числовая проверка: 80 шагов, 8 случаев, точные биты. Стенд с работающими теплообменниками: 10 шагов, полный масштаб и хеш `c5e01e6e180d2c4a`. Родитель проверил reports/exit-файлы и наблюдаемое состояние.

Обычный окончательный benchmark: мегабаза 20 716 объектов 10,979 → 10,662 мс/тик; 10 000 лент с модами 4,715 → 4,385; снимок 1,345 → 1,145. Поезда и кооперативный хеш изменились в другую сторону (0,186 → 0,213 и 0,037 → 0,043). Это один сравнительный прогон средних величин, не доказательство отсутствия регрессии по старому REF-p95 к 1.15.

Первая попытка полного npm test завершилась EPERM на удалении старого общего D:/tmp. Она сохранена как `parent/final-npm-test.log`, exit 1. После переносимого tmp тест пройден целиком. Ранее отвергнуты: вариант с WeakMap на каждом чтении, временная подмена chunkAt и тест только наличия внутреннего поля. Их данные сохранены; структурный RED по имени поля не считается поведенческим доказательством. Действительные RED: 67 чтений статуса вместо 32 и два лишних WeakMap.get на обычном пути.
