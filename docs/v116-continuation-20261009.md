# Продолжение 1.16 — этап восстановления бота

## Результат и границы

Версия остаётся **1.16.0-rc.7**. Это обновление инструментов разработки и приёмки, не финальный релиз 1.16.0. Файлы `src/` побайтно совпадают с исходным архивом: физика, сохранения, сетевой авторитет и пользовательский интерфейс не изменялись. Новый игровой архив не нужен: исправления относятся к ботам и тестам.

Закрыта воспроизведённая остановка botdef на пути к iron-chest (-506.7, 538.4). Исходный botdef завершился exit 1 с тем же BotError; после исправления неизменённый тест прошёл exit 0. Полный существующий npm test, без удаления или обхода прежних команд, завершился exit 0, включая tail-проверки. В цепочку добавлен новый bot-lifecycle.test.ts.

## Изменения

- Bot ожидает штатное возрождение через настоящие Game.step, идёт к телу и забирает инвентарь штатной командой pickup. Телепорта, выдачи предметов, изменения HP или таймера возрождения в реализации нет.
- Главный генератор и Bot.run проверяют необходимость восстановления перед продолжением прерванной задачи. Это покрывает и смерть/возрождение внутри пакетного yield.
- Прерванный путь пересчитывается после восстановления; обычные попытки обхода препятствий не расходуются на ожидание возрождения.
- Сохраняется реальная проверка переполненного инвентаря и недоступного тела. Повторная гибель не маскируется успешным восстановлением; число повторов ходьбы ограничено.
- Уточнён допуск near: целевая клетка учитывает 0.25-клеточный допуск прибытия walker, чтобы фактическое положение оставалось в запрошенном радиусе.
- Счётчик смертей обороны обновляется на границе симуляции, а не только при периодическом guard. Завершающий review добавил отдельный тест этого счётчика; финальный целевой запуск содержит пять сценариев.

Изменённые файлы: package.json, tools/bot/core.ts, tools/bot/script.ts, tools/bot/defense.ts. Новый тест: tests/bot-lifecycle.test.ts. Полный патч: integration-logs/continuation/bot-recovery.patch.

В полном npm test целевой lifecycle-тест успел исполнить четыре основных сценария до добавления завершающей проверки счётчика смертей; этот дополнительный сценарий вместе с предыдущими четырьмя прошёл отдельный финальный запуск. Новый счётчик уже присутствовал при исполнении botdef в полном наборе. Это не immutable release-freeze и не объявление завершения всей приёмки.

botdef-after: 2.5 игровых часа, 3 радара, 2 поста / 8 пулемётных турелей, 2 принудительных набега / 32 атаки Роя, 183 уничтоженных юнита. Инженер жив, патроны у всех турелей, проверки save/load совпали. Это ускоренные игровые часы, не ручной плейтест.

Первый GPU-запуск упёрся в отсутствующий Chromium. После установки браузера, соответствующего pinned Playwright, основной тест прошёл. Проверены реальная потеря/восстановление контекста, восстановление атласа, неизменённое полное сохранение Worker, очистка старого контекста и RU/EN-сообщения при инъекции отказа. Использован **программный SwiftShader**, не RTX 4060; историческая гонка F3 в этом запуске не воспроизвелась. Тест и UI не менялись. Новые кадры сохранены в integration-logs/continuation/gpu-screenshots; исторические кадры восстановлены из исходного ZIP.

56 файлов исходной tests/saves (включая манифест) проверены на побайтное совпадение с архивом. npm run saves здесь не запускался. Исходный контракт не менялся. AGENTS.md в переданном архиве не найден.

Функциональные проверки запускались параллельно; их времена не используются для оценки REF, heat или аппаратного FPS. Окружение: Amazon Linux 2023, Node 24, Intel Xeon 2.90 GHz, Playwright 1.62.0 / Chromium 151.0.7922.34.

## Следующий отдельный этап

**Цель:** устранить отказ водоснабжения обычного полного бота без подмены сценария, материалов и команд. Исходный npm run bot воспроизвёл отказ «не проложить трубу water-p от -172,-605» на tick 971317 (4:29 игровых часа). Снимок и отчёт: integration-logs/continuation/bot-before-final.z7save и bot-before-report.json. Диагностика реального сохранения: ordinary-bot-inspect.log; новая станция имеет пустую, не соединённую с насосом водяную сеть. Состояние не является полным снимком памяти планировщика Bot.

После изменений восстановления полный npm run bot до ракеты **не повторялся**. Успешный botdef и npm test не заменяют эту проверку. Следующий этап начать с диагностики pipeOk/routePipe и фактических портов/целей, отдельно отличить блокировку начальной клетки от исчерпания бюджета поиска. Локальное водоснабжение станции допустимо только как настоящая стройка с расходом материалов и проверенной паровой выработкой, не как фиктивное добавление целей в netTiles.

Также остаются открытыми строгие split/merge heat-бюджеты и одиночный рывок аварии, REF против 1.15, полный mega с прежними golden, общий E2E Chromium/Firefox/WebKit, настоящая потеря фокуса рельсовой кисти и полная ручная/длительная приёмка. На этом этапе они не повторялись и не объявляются исправленными. GPU-green одного окружения не аннулирует прежний отрицательный результат другой машины. Механики 1.17 не добавлялись.
