# Бесплатная служба приглашений 1.17

По ответу пользователя «подбери бесплатный» выбран **Render Free Web Service** для первого публичного стенда. Платный VPS и покупка домена больше не предлагаются. Конфигурация — `render.yaml` в корне исходников: один Node-процесс, `plan: free`, регион Frankfurt, ручные обновления. Игра/симуляция/сохранения остаются на ПК владельца, в облаке — приглашения и WSS-пересылка.

Действующий адрес пользователя: **https://zavod7-relay.onrender.com**. Render предоставляет TLS и WebSocket; домен покупать не требуется. Источники: [Web services](https://render.com/docs/web-services), [WebSockets](https://render.com/docs/websocket).

## Бесплатные ограничения

- После 15 минут без входящих HTTP-запросов или WebSocket-сообщений сервис засыпает. Пробуждение по обращению занимает около минуты; первая попытка входа может потребовать ожидания/повтора.
- 750 бесплатных часов на весь workspace в месяц. Трафик и минуты сборки имеют общие месячные лимиты; их актуальный остаток виден в кабинете. Без платёжного метода исчерпание трафика приостанавливает бесплатные сервисы до следующего месяца, исчерпание минут — новые сборки. При добавленном платёжном методе возможна доплата за превышение. Для варианта без расходов не добавлять оплату и не переключать compute plan.
- Процесс может перезапускаться в любое время; диск временный. Комнаты восстанавливаются регистрацией живого сервера владельца. Прежний короткий код вычисляется из сохранённого приглашения, но внешний перезапуск ещё требует приёмки на Render.
- У Render нет обещания пригодности Free для production; это стенд/хобби-вариант. Короткая функциональная проверка16клиентов прошла; длительная ёмкость и расход трафика ещё не измерены. Бесплатные часы не означают безлимитный relay.

Проверено по [официальным условиям Free](https://render.com/docs/free) 20 октября 2026. Не используются искусственные HTTP-прогревы или обход квот.

## Подключение

1. Создать бесплатный аккаунт Render и подключить [SpaceDazher/WebFactory](https://github.com/SpaceDazher/WebFactory). Проверенная `main` на коммите `7ed7250` содержит 1.10.0 без нового сервера. Текущая 1.17 опубликована в отдельной ветке [codex/v117-render-free](https://github.com/SpaceDazher/WebFactory/tree/codex/v117-render-free); выбрать её. Main не менялась. Это проверенный dev-кандидат, а не принятый финальный релиз.
2. В Render: **New → Blueprint**, выбрать репозиторий и корневой `render.yaml`. Проверить **Free**, один сервис, без базы данных и диска. Не включать платный план. Источник: [Blueprint](https://render.com/docs/blueprint-spec).
3. Дождаться сборки и взять фактический HTTPS-адрес сервиса. `RENDER_EXTERNAL_URL` и `PORT` читаются автоматически; явные `ZAVOD_RELAY_PUBLIC_ORIGIN` / `ZAVOD_RELAY_PORT` имеют приоритет. Строгая проверка origin/порта сохранена. `ZAVOD_INVITE_ORIGIN` задаётся на время сборки из выданного URL. Источники: [переменные](https://render.com/docs/environment-variables), [Node](https://render.com/docs/node-version).
4. На ПК владельца задать для штатного сервера `ZAVOD_RELAY_URL=wss://<фактический-хост>/v1/host` и `ZAVOD_RELAY_PUBLIC_ORIGIN=https://<фактический-хост>`. Для сборок игры/Windows-установщика перед сборкой задать `ZAVOD_INVITE_ORIGIN=https://<фактический-хост>`. Не подставлять пример как существующий адрес.
5. Проверить `/` и реальный WSS-вход с другой сети: короткий код, полную ссылку, переподключение после ухода гостей, перезапуск шлюза и прежний код/срок приглашения. Проверить квоты в кабинете. Только после этого адрес можно включать в поставку по умолчанию.

Старт: `node dist/native/relay-gateway.mjs`; сборка в Linux — команда из Blueprint. Секреты, admin capability, `.env`, сохранения и журналы в репозиторий не отправлять. Регистрация public использует подпись идентичности сервера; общий host-token не нужен. `ZAVOD_RELAY_TRUST_PROXY=0` сохраняет лимиты по адресу сокета, не доверяя неподтверждённым forwarded-заголовкам; на публичном стенде отдельно измерить влияние общих адресов прокси.

При выборе **Web Services → New Web Service** вместо Blueprint те же настройки вводятся вручную:

| Поле | Значение |
| --- | --- |
| Repository | SpaceDazher/WebFactory |
| Branch | codex/v117-render-free; либо main после принятия переноса |
| Language | Node |
| Root Directory | пусто |
| Region | Frankfurt |
| Instance Type | Free |
| Build Command | `npm ci --include=dev && ZAVOD_INVITE_ORIGIN="$RENDER_EXTERNAL_URL" npm run native:server` |
| Start Command | `node dist/native/relay-gateway.mjs` |
| Health Check Path | `/` |
| Environment | `NODE_VERSION=22.23.2`, `ZAVOD_RELAY_REGISTRATION=public`, `ZAVOD_RELAY_TRUST_PROXY=0` |

Выданные самим Render `RENDER_EXTERNAL_URL` и `PORT` вручную не выдумываются. Для первоначального стенда достаточно собственного onrender.com-адреса, без custom domain и дополнительных сервисов.

## Локальные и публичные проверки

Настоящий packaged-процесс с `RENDER_EXTERNAL_URL`/`PORT` прошёл TLS/lifecycle-проверку `npm run test:native117 -- --relay --invite-only --render-env` (exit 0). Прежние явные переменные отдельно проверяются с конфликтующими provider-переменными, чтобы сохранять приоритет. Это проверяет точку запуска приложения, а не развёртывание Linux/Render.

Пользователь развернул сервис: **https://zavod7-relay.onrender.com**. Страница приглашений отвечает200; чужой Origin отвергается. Настоящий отдельный сервер и16синтетических сетевых клиентов завершили один публичный HTTPS/WSS-прогон0 (`public-render-diagnosis.log`), включая вход/пароль/white-list/переподключение/stop-start. Другие попытки нагрузки дали таймаут повторной публикации и обрыв до первого снимка. Отдельно воспроизведена задержка старого туннеля после release: свежая подпись той же установки отклонялась. Исправление ac05429 допускает замену только освобождённого сокета с тем же lease; активный мир и другой lease защищены. Пользователь подтвердил новый Live deploy. Длительная стабильность16 на Free ещё не принята; короткие результаты и точные журналы приведены в отчёте приёмки.

Сборка игры и Windows-компонента выполнена с `ZAVOD_INVITE_ORIGIN=https://zavod7-relay.onrender.com`; адрес встроен в клиент и native bundle без секретов. `npm run test:native117 -- --relay --browser --ws-only --en --provider-default` с `ZAVOD_ACCEPTANCE_RELAY_ORIGIN=https://zavod7-relay.onrender.com` завершился0: настоящий Chromium входит по полной ссылке и короткому коду, гости отделены от владельца, повторный вход и движение владельца работают. У дочернего сервера нет явных ZAVOD_RELAY_URL/PUBLIC_ORIGIN — проверяется именно встроенный provider. Публичный сертификат проверяется стандартно, без тестовой CA/SPKI-исключения. Журнал: `logs/acceptance-20261020/public-render-browser.log`.

Для повторения сборки из исходников задать переменную перед `npm run native:build`, как в `native/README.md`. Сам адрес не является паролем или токеном; индивидуальные ключи установок и игровые приглашения остаются локальными. Ветка отправляется штатным Git/GCM с выбором SpaceDazher; main не меняется. Развёртывание Free не заменяет длительную проверку или приёмку установщика.

После Live deploy ac05429 отдельные public-render-live-browser и public-render-live-players-final завершились0: новые миры, реальные HTTPS/WSS без TLS-исключений, встроенный адрес, браузерные ссылка/код/движение и16независимых клиентов с переподключением. Полный npm test после правки gateway также завершился0. Длительная приёмка и установка Windows остаются незакрытыми.
