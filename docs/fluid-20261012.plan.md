# Continuation-11: сокращение затрат массовой аварии

Новый ограниченный этап после continuation-10, 12 октября 2026. Версия остаётся 1.16.0-rc.7. Базовая копия: D:/Project/webfactory/work-v116-reactor-power-20261012; рабочая: D:/Project/webfactory/work-v116-fluid-20261012. Производственные SHA входа сохранены в docs/continuation-11-input-source-sha.json. Исторические документы являются данными, а не новыми разрешениями.

## Цель и границы

Измерить оставшиеся затраты первого взрыва на прежнем полном стенде и уменьшить стоимость пересборки жидкостных сетей без изменения игровой физики, порядка обхода, числовых значений, сообщений и состояния сохранений. Инженер получает тот же результат аварии с меньшей задержкой. Производственные изменения ограничить rebuildFluids и необходимой внутренней поддержкой World; другие изменения требуют доказанной необходимости в рамках того же узкого этапа. Публичный boxNeighbors сохранить. Драйверы, пользовательский Chrome, баланс, UI и механики 1.17 вне этапа.

## План реализации

1. Прочитать существующий полный измерительный скрипт candidate-cycle2-pair-1.once.ts и два подходящих теста. Для диагностики адаптировать существующий стенд: только импорты и пути результатов; дополнительные диагностические счётчики/профайлер разрешены в отдельно помеченном диагностическом прогоне. Его время не использовать для окончательного A/B.
2. Перед производственным кодом добавить поведенческий тест повторной работы выбранного горячего пути и наблюдать действительный RED на исходном коде. Проверить порядок сетей/узлов, фильтры рецептов и конфликты, точные amount/se, подземные трубы, изменения и переопределения World/entAt, если выбранная оптимизация их затрагивает. Существующие фикстуры и ожидания не ослаблять.
3. Реализовать наименьшее исправление, получить GREEN тем же тестом и связанными существующими тестами. Нельзя переносить работу за Game.step или менять масштаб, состояния, прогрев и пороги измерения.
4. Проверить сравнение continuation-10/новой версии после каждого шага, включая предупреждения и числовые биты. Адаптировать четыре существующих parity-скрипта с заменой только источников и путей выхода.
5. Провести две чистые последовательные пары baseline → candidate без конкурирующих тяжёлых процессов. Использовать прежнюю физическую фикстуру: 100 реакторов, 12 300 теплопроводов, 1000 теплообменников, 2000 турбин, 200 настоящих насосов; прежние 300 шагов прогрева, 1800 отсчётов стационарных стадий, 30 разрывов/соединений и 600 шагов до первого взрыва. Сохранять сырые массивы и все отказы.

## Приёмка этапа

- Все сравнения состояния/числовых битов точны; прежние хеши не переписываются.
- Оба кандидата: p95 тепла ≤6 мс и p95 полного Game.step ≤16.67 мс на каждой прежней стадии; максимум первого взрыва сообщается отдельно.
- Среднее двух пиков первого взрыва кандидата ≤90% среднего двух соседних baseline; ни одна пара не ухудшает пик больше чем на 5%. Две пары доказывают только локальный эффект, не универсальную гарантию.
- Существующие build, typecheck, полная i18n, полный npm test, test:nuclear-long и обычный bench проходят с exit 0. Parent самостоятельно проверяет дифф, сырые результаты и исполняемые проверки. Не имитировать покрытие 80% при отсутствии настроенного coverage-runner.
- package-lock и все старые npm test команды сохраняются; разрешено добавить только новый релевантный тест.
- Новый RC архив игры/исходников содержит согласованные сборку, отчёт и продолжение; SHA256 и прочитываемость всех ZIP файлов проверены.

## Проверки и доказательства

Использовать только локальные проектные команды: npm.cmd run build; npm.cmd run typecheck; npm.cmd exec -- tsx tools/i18n-check.ts --full; npm.cmd test; npm.cmd run test:nuclear-long; npm.cmd run bench; npm.cmd exec -- tsx tests/<релевантный существующий или новый тест>. Все команды, exit codes и логи сохраняются под integration-logs/continuation-11/fluid. Отчёт содержит RED/GREEN и отдельные непроведённые проверки. Браузерная матрица, ручной плейтест, полный REF к 1.15 и приёмка всей версии не выдаются за выполненные этим этапом.

## Ограничение цикла

Ровно один субагент GPT-6-Luna max, не более трёх реализационных циклов с консолидированными исправлениями от parent. Не создавать заменяющих агентов ради обхода лимита. Если после трёх циклов критерии не достигнуты — сохранить свидетельства, сообщить конкретный непрошедший критерий и следующий шаг; не выпускать непроверенную оптимизацию как успешную. Не создавать durable goal без отдельного запроса пользователя.

## Уточнение последнего цикла по наблюдаемым данным

C1 отклонён: кэш occupancy дал средний пик 96.0008% baseline и одну пару +7.6938%; оба кандидата превысили heat p95. C2 заменил временные Entity/box tuples локальными параллельными массивами; функциональные проверки точны, но средний пик 96.585% baseline, а split heat p95 6.6678/6.8670 мс. Эти отказы сохранены; пороги и приёмка не меняются.

Профиль C2 показал 60 локальных пересборок по 100 изменённых ID. В split heatNet p95 около 1.86 мс, storage.finish около 0.57 мс, сборка после finish около 0.80 мс, при полном heat p95 около 7.03 мс. В split удалённые ID не вызывают heatNeighbors, поэтому предложение переиспользовать только neighbor buffer отклонено до реализации.

Последний C3 может затронуть heat.ts и необходимую поддержку heat-cache.ts, только чтобы убрать повторную полную сборку edgeFlat/pipeFlat при изменении графа. Канонический обход страниц/строк должен сохранять все операции и порядок, совместимые плоские поля — прежние числовые значения при чтении. Дополнительно разрешено убрать временные записи/обратные callback-поиски соединений внутри rebuildFluids через приватное компактное представление; публичный fluidConns/boxNeighbors и rotLocal остаются прежними. Сохранить локальные scratch arrays C2. Для каждого нового механизма нужен действительный RED перед соответствующим производственным изменением, точная parity, прежние две тихие пары и все пороги. Изменения тестов ограничены одним новым fluid test и уже включённым heat-local-rebuild.test.ts; старые команды npm test сохранены. После C3 — приёмка или конкретный отчёт о непрошедших критериях, без четвёртого цикла.
