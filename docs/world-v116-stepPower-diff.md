# `stepPower` differential evidence

The cycle-3 differential imported the immutable `../parallel-base-v1.16` `Game`, save, and `stepPower` modules before the release modules to preserve their existing ESM initialization order. Both sides loaded the same `REF_BASE` save through their own deserializers. The fixture contained 1,906 entities, one electric network, and 12 steam-fluid networks.

For 2,400 direct power steps, both sides received identical active/standby states, per-entity priority tiers, roboport charge, and periodic steam replenishment. The per-step comparison covered every power network's demand, supply, satisfaction, tier shares, load, history, storage flow, solar and steam output; all entities' network, priority, cut, buffer request, max/output/work, charge and active fields; all fluid amounts/energy; generator-energy statistics; and turbine joules. There were no mismatches. The comparison excludes `pstats.ec` because immutable base records prior-tick consumption while v1.16 intentionally records same-tick allocated consumption; the same-prototype, mixed-tier plus roboport-buffer assertions are in `tests/v116b.test.ts`.

Result: [`world-v116-stepPower-cycle3-diff.log`](../integration-logs/world-v116-stepPower-cycle3-diff.log). The production scratch now stores reusable per-network entity and actual-kW arrays; it preserves network/entity addition order while removing the former global buffer, tier, and linked-index arrays.

The separate 1,800-tick full `Game.step()` canonical save comparison is [`world-v116-full-canon-cycle3.log`](../integration-logs/world-v116-full-canon-cycle3.log). After normalizing only additive v1.16 depletion state, the legacy `genv=1` alias, empty management defaults, and intentional same-tick consumption metrics/rollups, it reports zero other serialized differences across 1,906 entities. Raw hashes are expected to differ because those fields are part of the product change.

Targeted checks after the scratch change: `npm.cmd exec -- tsx tests/v116b.test.ts`, `npm.cmd exec -- tsx tests/v116.test.ts`, `npm.cmd exec -- tsx tests/v115.test.ts`, `npm.cmd exec -- tsx tests/v116vehicle.test.ts`, `npm.cmd run typecheck`, and `MEGA_QUICK=1` `tests/mega.test.ts` all exited 0.

The final strict timing probe ran as `node --import tsx --input-type=module -e $taskProbe` in the parent-confirmed quiet window on 2026-10-09. It compared the actual v1.15 `REF_BASE` deserializer against the current release using the same 1,906-entity fixture, 3,600 warm ticks per side, three rounds of 4,800 sampled ticks per side, 120-tick alternating/interleaved blocks, reversing the first side each round. Raw per-tick measurements (14,400 per version) are in [`world-v116-perf-cycle3-samples.json`](../integration-logs/world-v116-perf-cycle3-samples.json); summary and per-round percentiles are in [`world-v116-perf-cycle3.log`](../integration-logs/world-v116-perf-cycle3.log).

Pooled p95 was 0.7742 ms for v1.15 and 0.8650 ms for current, ratio 1.117282; thus the relative 1.10 limit failed, while the absolute 16.67 ms limit passed. Individual round p95 ratios were 1.123721, 1.100308, and 1.128288. The host reported a 12th Gen Intel Core i7-12650H (10 cores/16 logical processors) on Windows 11 Pro. Timing was isolated to the designated quiet window, after UI E2E15 had exited and with other agents instructed to hold execution. CPU temperature or thermal throttling telemetry was not captured, so the result does not establish a thermally stabilized benchmark.
