## Браузерная сторона отдельного сервера

Родитель добавил `client/native.ts`, `ui/nativeui.ts`, мост remote в
`client/mirror.ts`, интеграцию main/MpUI и RU/EN. Контроллер доступен только
с локально выданным capability: fragment удаляется из URL до hooks, один
bootstrap выдаёт отдельные control bearer/CSRF и gameplay join token;
секреты остаются в памяти. Полный серверный протокол и worker freeze/resume
реализует тот же Luna в своих файлах. Это исходники, не доказательство
работы приложения или готового установщика.

Передача готовит transaction до freeze, экспортирует закрытый тик и hash,
ждёт durable commit. Потерянный HTTP ответ оставляет старый авторитет
замороженным; только подтверждённый abort/expiry разрешает resume.
Состояние unresolved блокирует выбор другого мира и замену модов.
Подключение принимает снимки существующей Game через общий typed-array
codec; игровой ввод и запросы статистики/сохранения идут на сервер.
Отсоединение не возобновляет старый локальный Worker. Явный выбор новой
локальной партии снимает remote-режим. Серверные auto-save принадлежат
процессу сервера, клиент их не дублирует. Меню клиента не ставит сервер
на паузу; пауза/скорость отправляются только владельцем.

В меню добавлены реальное состояние, старт/сохранение-остановка, выбор
локального мира, 8/16 игроков, приглашение, переподключение, восстановление
неопределённой передачи. Скачать установщик предлагается только после
обнаружения настоящего packaged EXE, не HTML fallback. Guest URL использует
same-origin gameplay и удаляемый `server-invite`/`server-reconnect` fragment;
административный доступ гостю не выдаётся. Текущие интернет/relay и Windows
артефакты ещё не приняты. Проверки запуском по-прежнему не выполнялись.

Позже подключён персональный `MpClient.nativeMigrate`: после durable commit
старый host отправляет каждому существующему peer только его reconnect
capability через текущий authenticated канал и ждёт ограниченный ACK.
Клиент принимает директиву только от текущего host, проверяет URL/token/срок
и переходит к served game через `server-reconnect` fragment. Имя не является
идентичностью, control bearer никому не отправляется. HTTP handoff использует
общий typed-array codec и отдельный предел 128 MiB, gameplay frames — 8 MiB.
Исполнитель начал настоящие `src/native/server.ts` и `websocket.ts`; файлы
находятся в работе. Родитель передал замечания по разделению join/control
credentials, крупным снимкам, backpressure, boundary скриптов и срокам epoch.
Это ещё не подтверждение их исправления или работоспособного сервера.

Для больших миров добавлен browser assembler snapshot-begin/chunk/ACK:
одна ограниченная передача до 128 MiB, части по 384 KiB, последовательные
индексы, точные длины, UTF-8, tick, checksum, modSet; применение только
после полного набора. Последний ACK идёт после успешного применения.
Прогресс и отмена видимы в UI; старые queued frames после выбора другого
мира отвергаются по socket/generation. Idle timeout 30 с и общий предел
передачи 180 с. Исполнитель обновил `nativeWireHash` с BigInt на hi/lo32
FNV1a64; векторам и производительности ещё нужна отложенная проверка.
Bootstrap выдаёт только control bearer/CSRF, игровой owner token берётся
отдельным авторизованным join-token запросом. Invite clipboard и сам код
скрыты, пока native status не подтвердил route ready.

Loopback control page и gameplay используют разные порты: bootstrap сообщает
проверяемый loopback `playOrigin`, владелец открывает WS там, гость — на
origin приглашения. Mirror переносит доверенный dedicatedServer context для
лимитов 16-местного сервера. Статические замечания о повторном bootstrap
(нужна защита launcher credential, а не один Origin), общей очереди sfx/
achNew при per-peer снимках и nucEv переданы исполнителю; их финальное
состояние ещё предстоит независимо принять.

Guest reconnect теперь хранит только личный игровой credential в scoped
browser storage по origin/worldId (до 16 миров), отдельно от административных
секретов. Public world-info не выдаёт токенов и позволяет выбрать правильную
запись перед входом. Серверный clientId — случайные 128 бит, сохранённые у
этого профиля браузера; повтор первой авторизации с потерянным welcome не
создаёт второго инженера. Обычный guest reconnect token больше не сжигается
перед доставкой welcome. Явный migration/reconnect fragment имеет приоритет
над прежней записью браузера. Закрытие вкладки/повторный вход ещё требуют
отложенного запуска; эти свойства не объявлены принятыми.

- В диагностику добавлены причины биосбора/проб/капсул/биогеля/биошлама.
  Новые правила оповещения: мало капсул, заполненный пункт, истечение
  останков. Область останков сохраняется как bioArea с ограниченными
  координатами/радиусом; показывается подсветкой без подмены corpse id на

  Планировщик сопоставляет требуемое биосырьё с наблюдаемым сбором и явно
  ограничивает обещаемый устойчивый выпуск. При сборе санитарным роботом
  расход/добыча относится к его станции, выгрузка повторно их не создаёт.

- Добавлены справочник в окне управления и контекстные подсказки ОСКАРа
  для генолаборатории/библиотеки/банка, фабрикатора, пункта управления,
  боевого дронопорта и громкоговорителя. Таблицы берут 15 видов/вес W,

  Общие тексты RU/EN находятся в `data/reference117.ts`, таблицы — в
  `ui/reference117.ts`. Дополнены шесть отсутствовавших подписей новых
  подкладок в BIO_LINING_LABELS; значения эффектов не изменены.

- Сохранены родительские §8 (насыпь/кэши/снимки), §11 (назначение и показ
  жидкостных портов), §4 (текущий самый громкий источник группы без

- Исполнитель продвигает биоформы: питание/пустая тара/пункт управления,
  команды отрядов, оплаченный фабрикатор и живое заблокированное тело,
  переносной пульт, именные группы. Часть последних изменений пока
  подтверждена только сообщениями исполнителя; нужна независимая сверка

  замедления требуют проверки границ загрузки, а не только хеширования.

## Родительская реализация §10

`src/sim/polechain.ts` задаёт общий DDA для авторитета и предпросмотра.
Расстояние берётся между фактическими центрами с `min(wireA, wireB)`;
равные полуклетки округляются к +infinity. Для прямого жеста сохраняется
исходная точка луча; при повороте новый луч начинается от подтверждённой
опоры. Проверка связи перед оплатой выполняется и общим расчётом, и
обработчиком размещения. Доступные кандидаты рассматриваются от дальних
к ближним; существующая подходящая опора принимается без новой оплаты.

Команда `poleChain` выполняет максимум 16 шагов атомарно, без фоновой
очереди оставшегося пути. Клиент ждёт подтверждения до следующего пакета.
Один маленький журнал на стабильного владельца содержит high-water
gesture/seq и последний результат: старые/повторные команды не строят
второй раз, cancel закрывает жест. Журнал сохраняется в save21, проверяется
при загрузке, включён в hash/snapshot/mirror. Он не содержит зажатых
клавиш, таймера строительства или исполняемого будущего пути; загрузка
сама ничего не строит. Состояние мыши существует только в main.ts.

Game использует обычную оплату/проверку дальности, отдельный явный режим
призраков, групповой undo и штатную отложенную пересборку электросети.
Mouseup не достраивает короткий конец. Отмена охватывает Escape, смену
инструмента/мира/личности, меню, потерю кнопки/фокуса/указателя.
Общий слой рендера показывает якорь, следующий столб, будущий провод и
раздельные зоны питания; красный/зелёный провод не создаётся.

После статического разбора убран отдельный предел 512 кандидатов: он
мог пропустить доступное укорочение у модовой опоры с длинным wire.
Поиск ограничен конечным диапазоном карты; ванильный луч рассматривает
не более 32 клеток. Производительность большого модового wire и все
численные примеры, разные частоты событий мыши, сеть, save/load и
конфликты ещё требуют запуска после завершения остальных функций.

Изменённые места §10: новый helper; Game Cmd/поле/case; main input;
renderer View/overlay; save, compat, protocol, snapshot, client mirror,
nethash, EN117. Все места снова доступны исполнителю.

## Поздняя сверка рецептов и творческого режима

В `recipes.ts::V117_AMMO_TECH` добавлены пропущенные исходные технологии
для обычного/изотопного огнемётного топлива. Покрытие не должно обходить
исследование исходного боеприпаса.

В `x116.ts` найдена и исправлена потеря `.instance` при загрузке отложенных
вещей выживания: физический дрон сохраняет исходный ID, владельца,
здоровье, заряд, боезапас и остаток ремонта. Данные строго проверяются и
клонируются, повреждённый экземпляр не заменяется новым. При входе в
creative вложенные экземпляры тоже копируются. Выдача тестовых дронов
проходит через явную фабрику новых пустых экземпляров; обычный числовой
`Inventory.add` для них остаётся запрещён. `creative-return` проверяет
админа, запреты сценария, тип предмета и место; неверные/дробные количества
не должны становиться повреждёнными стопками. Sticky `cheatsUsed` ставится
при входе в creative и восстанавливается миграцией из `x.cheats/mode`.
Diff просмотрен; save/load/переключение режима/сеть ещё не запускались.

## Полевой генетический сбор и крупный экспорт

В `bioRobots.ts` добавлены отдельные режимы материала, генетических проб и
живых клеток, фильтр точного вида из 15, проверка исследования и
жизнеспособности при фактическом завершении. Вылет резервирует настоящие
капсулу и набор консервации; смена настройки не превращает груз в другой
режим. Неиспользованный набор возвращается при отмене, уничтожении робота
или демонтаже станции. Успешная проба списывает его ровно при единственном
уменьшении общего остатка трупа. Слизь сохраняет отдельную обычную операцию.

Поля станции/задания сохраняются обычными entity/robot spread-путями;
проверка входного сохранения и хеш охватывают режим, вид и физический
набор. Старые отсутствующие поля означают материал/все виды. Дополнен
хеш ручного задания: ранее он не различал режимы. Snapshot signature
передана тому же исполнителю, владеющему `snapshot.ts`.

Окно станции показывает фильтры, вход набора, ближайшие сроки донорских
клеток и причины остановки. У ручного биосборника появился выбор режима;
HUD активного клеточного отбора показывает оставшееся игровое время.
RU/EN и диагностика дополнены. Это статические изменения, не приёмка:
повтор команд, конфликт с игроком, границы 10 минут, возврат и большие
скопления останков требуют последующего выполнения проверок.

`NativeClient` принимает одноразовый owner-only билет крупного экспорта
с control origin: ограниченный поток до 128 МиБ, точный размер, checksum,
UTF-8 и декодирование исходного RPC `{str,tick,info}`. Секрет передаётся
Bearer-заголовком, не URL; перенаправление запрещено, разрыв подключения
отменяет загрузку. Серверную выдачу билетов реализует тот же исполнитель.
Ни сервер, ни браузерный путь не запускались.

Сравнение в справочнике дополнено численным базовым уроном одного
попадания до исследований, отдельным кислотным компонентом и примером
остаточного урона подкладки после обычной брони. Числа берутся из тех же
определений предметов; фактический бой ещё не проверялся.

При последней сверке §3.7 найден отдельный незакрытый пункт:
`scenario.ts` всё ещё использует `fmt: 2`; редактор ещё не разделяет
начальную союзную особь, вражеский источник, изученный геном и живую
культуру. Нужна отдельная вертикаль `fmt: 3` с пустой миграцией старых
сценариев, проверкой запретов/владельца/лимитов и применением только при
создании нового сценарного мира. Это нельзя считать реализованным по
наличию полей обычного save21. Передано тому же исполнителю как известный
остаток, чтобы не объявить функциональную фазу законченной преждевременно.

Полный состав смотреть по SPEC и ledger: ни один этот список не является
