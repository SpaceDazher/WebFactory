# Формат сценария `.z7scn` (v1.16)

Сценарий — это текстовый файл JSON: **карта + правила + цели + необязательный скрипт**. Его делает редактор карт
(Esc → «Редактор карт»), сохраняет в браузере (IndexedDB) и выгружает в файл («Экспорт в файл»). Друг открывает файл
(Esc → «Испытания» → «Открыть сценарий из файла») и играет на той же карте; у всех игроков совместной партии карта,
правила и цели одинаковы — они входят в состояние партии и в контрольные суммы.

Пример: [`example-training.z7scn`](example-training.z7scn) (чистая карта 64×64, четыре пятна ресурсов, три цели).

## Поля

```jsonc
{
  "fmt": 1,                     // прежний формат; в 1.16 также поддерживается fmt: 2
  "id": "u-lk3j9a2x",           // идентификатор (a-z, 0-9, _ . -); «z7-…» зарезервировано за встроенными испытаниями
  "name": "Моя карта", "desc": "Описание", "author": "Имя",   // до 60 / 800 / 40 знаков
  "ver": 1,                     // ваша версия карты
  "seed": 12345,                // seed мира (для base = "gen" — генерация, для "blank" — только декор)
  "map": {
    "base": "gen",              // "gen" — обычная генерация по seed, поверх неё правки; "blank" — чистая трава
    "bounds": { "w": 100, "h": 100 },   // null — карта бесконечна; иначе 24…512, за краем — глубокая вода
    "edits": {                  // правки построчно: клетки y, от x0 до x1 включительно
      "terrain": [[y, x0, x1, вид]],    // вид: 0 трава, 1 песок, 2 камень, 3 мелкая вода, 4 глубокая вода
      "res":     [[y, x0, x1, ресурс, запас]],   // 1 железо, 2 медь, 3 уголь, 4 камень, 5 нефть; в fmt: 2 также 6 уран. Для нефти запас — дебит
      "decor":   [[y, x0, x1, вид]]     // 0 нет, 1 дерево, 2 скала
    },
    "nests": [{ "x": 0, "y": 0, "proto": "biter-spawner" }],   // biter-spawner, spitter-spawner, worm-small, worm-medium
    "ents":  [{ "proto": "wooden-chest", "x": 3, "y": 4, "dir": 0, "recipe": null }],   // готовые постройки
    "start": { "x": 0, "y": 0, "w": 8, "h": 8 }   // область старта: инженер появляется в её центре
  },
  "rules": {
    "enemies": "normal",        // none | peaceful | normal | deathworld (настройка «Рой» партии; в сценарии не меняется)
    "nests": "auto",            // auto — гнёзда как в обычной игре; custom — только заданные в map.nests; none — без гнёзд
    "nestMin": 260, "nestDens": 1,       // для auto: ближайшие гнёзда (в клетках от старта) и множитель густоты
    "startItems": { "iron-plate": 50 },  // стартовый инвентарь; null — обычный («обломки корабля»)
    "techs": null,              // список разрешённых технологий; null — все
    "preTech": [],              // изучены в начале (вместе с предками)
    "ban": ["transport-belt", "type:belt"],   // запреты: id предмета/постройки или «type:<тип>» (belt, underground, splitter, rail, loco, wagon, stop, signal, roboport…)
    "timeLimit": 0              // минуты; 0 — без лимита. Время вышло — «испытание не пройдено» (играть можно дальше)
  },
  "goals": [                    // победа — когда выполнены ВСЕ цели; пустой список — свободная игра
    { "k": "produce",  "item": "iron-plate", "n": 200 },
    { "k": "build",    "proto": "steam-engine", "n": 1 },      // proto может быть «type:lab»
    { "k": "research", "tech": "automation" },
    { "k": "survive",  "min": 30 },
    { "k": "rocket",   "n": 1 },
    { "k": "kills",    "n": 100 }
  ],
  "script": ""                  // необязательно: обычный control.js мода (API v1.11), до 60 КБ
}
```

## Формат 2 и генератор мира

1.16 читает оба формата. Экспорт остаётся `fmt: 1`, если карта и её содержимое совместимы с 1.15. Настройки генерации, новый алгоритм мира, уран, новые предметы/постройки/рецепты/технологии и новые виды целей требуют `fmt: 2`; редактор определяет это по содержимому. Не меняйте номер формата вручную ради открытия новой карты в старой игре.

`gen` и `genv` — поля верхнего уровня. `genv` задаёт алгоритм генерации: 1 — прежний, 2 — связные месторождения и масштабируемые биомы. Старые `fmt: 1` и `fmt: 2` без `genv` используют алгоритм 1. Неизвестная версия генератора и `fmt` больше 2 отклоняются с сообщением об ошибке. Чистая карта `map.base: "blank"` не получает новые случайные залежи из-за смены генератора.

Пример дополнительных полей карты с изменённым количеством воды:

```json
{
  "fmt": 2,
  "genv": 2,
  "gen": {
    "water": 1.25,
    "size": [1, 1, 1, 1, 1, 1, 1],
    "rich": [1, 1, 1, 1, 1, 1, 1],
    "freq": [1, 1, 1, 1, 1, 1, 1],
    "spacing": [1, 240, 240, 270, 300, 440, 650],
    "biomeScale": 1.5,
    "uranium": true
  }
}
```

Массивы индексируются номером ресурса 1–6; нулевой элемент служебный. `water` и `size`: 0,5–2; `rich`: 0,25–4; `freq`: 0,25–2; `biomeScale`: 0,5–2. `spacing` — расстояние в клетках, округляется до десятков и ограничивается диапазоном, зависящим от ресурса и его частоты. Одинаковые seed, `gen` и `genv` дают одинаковую карту независимо от порядка открытия чанков. Настройки находятся в редакторе на вкладке «Карта», блок «Вода и ресурсы».

Две дополнительные цели `fmt: 2`:

```json
[
  { "k": "power", "min": 30 },
  { "k": "consume", "item": "used-nuclear-fuel-cell", "n": 5 }
]
```

`power.min` — электрические МВт штатных паровых турбин, удерживаемые 60 игровых секунд подряд. После загрузки эта минута отсчитывается заново. `consume` обычно считает фактический расход указанного предмета; для отработанных ячеек учитывается завершённая переработка, а не загрузка на вход центрифуги. При экспорте и импорте ID карты может измениться, смысл этих целей сохраняется.

## Запреты и технологии

* Запрещённое нельзя ставить («Запрещено правилами испытания»), рецепты запрещённых предметов убираются из списка
  крафта, технологии, которые отпирают только запрещённое, остаются, но их рецепты не появляются.
* Технология вне списка `techs` серая и не исследуется; зависящие от неё тоже. Игра сама добавляет предков
  разрешённых технологий в `preTech`.

## Скрипт сценария

Скрипт запускается как ещё один мод (`scn-<id>`) в той же песочнице, что и скрипты модов (API v1.11: `game.on_tick`,
`game.print`, `game.create_entity`, `game.remove_entity`, `game.insert`, `game.remove_item`, `game.gui`, `game.storage`; описание — в README, раздел v1.11). Добавлено:

* `game.scenario.win(текст)` — объявить победу (итог «пройдено»), `game.scenario.fail(текст)` — поражение.
  Вне сценария вызов только пишет предупреждение.

## Что делает игра с чужим файлом

Файл — недоверенные данные. Всё проходит проверку: значения вне диапазона отбрасываются вместе со строкой правки,
неизвестные предметы, постройки и технологии пропускаются (с предупреждением), число правок, построек, гнёзд, целей
и размер файла ограничены (файл — до 4 МБ). Скрипт работает в песочнице и не получает доступа к странице. id вида
`z7-…` из файла получает префикс `u-`: достижения и таблица результатов — только у встроенных испытаний.

## Встроенные испытания (id)

| id | Название | Особенности |
|---|---|---|
| `z7-rocket-8h` | Ракета за 8 ч | врагов нет, лимит 480 мин, обычный старт |
| `z7-no-belts` | Без конвейеров (только роботы) | запрещены конвейеры, подземные, разветвители, рельсы, поезда, сигналы |
| `z7-island` | Остров | карта 100×100, чистая, пять пятен ресурсов, без гнёзд |
| `z7-deathworld` | Смерть-мир | гнёзда от 130 клеток, густота ×1,5, быстрая эволюция |
| `z7-trains` | Только поезда | запрещены конвейеры, роботы, личный робопорт |
| `z7-atomic` | Атомный пуск | добыть уран, изготовить топливо, удержать 30 электрических МВт 60 секунд и завершить переработку пяти отработанных ячеек |

## Где что хранится

* Достижения и таблица результатов — `localStorage` (`zavod7.ach`, `zavod7.results`); переживают обновление игры.
  «Экспорт результатов и достижений» → файл `.json`, «Импорт из файла» объединяет (достижения — раньше выигрывает,
  в таблице — лучшие десять на испытание).
* Сценарии из редактора — IndexedDB (`scn:<id>`, список `scn:index`).
* Партия по сценарию (сохранение) хранит сам сценарий: загрузить её можно без исходного файла.
